# Master M/C Plan Dashboard

แดชบอร์ดวางแผนเครื่องจักร (BW / LC / CW) รันเป็นเว็บเซิร์ฟเวอร์บนเครื่องของคุณ ให้ทุกคนในวง LAN/WiFi เดียวกันเข้าดูและแก้ไขข้อมูลชุดเดียวกันได้ พร้อมแจ้งเตือนเข้า Microsoft Teams เมื่อมีการบันทึกข้อมูล

## วิธีรัน

```bash
npm install
npm start
```

จะเห็นข้อความ:
```
Master M/C Plan Dashboard กำลังทำงานที่ http://localhost:3000
```

เปิดเบราว์เซอร์ที่เครื่องนี้ไปที่ `http://localhost:3000` ได้เลย

## ให้เครื่องอื่นในโรงงานเข้าถึง

1. หา IP ของเครื่องนี้ในวง LAN: เปิด Command Prompt แล้วพิมพ์ `ipconfig` มองหา "IPv4 Address" (เช่น `192.168.1.50`)
2. เครื่องอื่นในวง LAN/WiFi เดียวกัน เปิดเบราว์เซอร์ไปที่ `http://192.168.1.50:3000` (แทนที่ด้วย IP จริงของเครื่องนี้)
3. ทั้งฟอนต์ ไอคอน และ Chart.js ถูกดาวน์โหลดมาเก็บไว้ในเครื่องแล้ว (`public/vendor/`) จึงใช้งานได้แม้เครื่องปลายทางบล็อค Google/YouTube — ไม่ต้องพึ่งอินเทอร์เน็ตภายนอกเลย
4. **ควรเปิดเครื่องนี้ทิ้งไว้ตลอดเวลา** เพื่อให้ทุกคนเข้าถึงได้ตลอด ถ้าต้องการให้รันอัตโนมัติเมื่อเปิดเครื่อง แจ้งได้ จะช่วยตั้ง Task Scheduler ให้

## ตั้งค่ารหัสผ่าน Admin

แก้ไฟล์ `config.json`:
```json
{
  "port": 3000,
  "adminPassword": "ตั้งรหัสผ่านใหม่ตรงนี้",
  "teamsWebhookUrl": ""
}
```
แก้แล้วต้อง **restart server** (ปิดแล้วรัน `npm start` ใหม่) การเปลี่ยนแปลงจึงจะมีผล

## ตั้งค่าแจ้งเตือนเข้า Microsoft Teams

Teams เลิกรองรับ "Incoming Webhook" แบบเก่าแล้ว วิธีปัจจุบันต้องสร้าง Workflow ผ่าน Power Automate:

1. เปิดช่อง/กลุ่ม Teams ที่ต้องการรับแจ้งเตือน → คลิก "..." ข้างชื่อช่อง → **Workflows**
2. ค้นหาแล้วเลือก template **"Send webhook alerts to a channel"** (ชื่อ template ของ Microsoft มีการเปลี่ยนเป็นระยะ ถ้าหาไม่เจอให้ลองค้นคำว่า "webhook" แล้วดูอันที่คำอธิบายพูดถึงการรับ alert จากเครื่องมือภายนอกแล้วโพสต์เข้าช่อง)
3. ตั้งค่าให้โพสต์เข้าช่องที่ต้องการ → ทำตามขั้นตอนจนเสร็จ ระบบจะให้ **URL ของ webhook** มา (หน้าตาแบบ `https://xxxxx.webhook.office.com/...`) ถ้าขั้นตอนไหนถามหา "sample payload" ให้ใส่ `{"text": "ข้อความตัวอย่าง"}`
4. คัดลอก URL นั้นมาใส่ใน `config.json` ช่อง `"teamsWebhookUrl"`
5. Restart server (`npm start` ใหม่)
6. ทดสอบด้วยคำสั่งนี้ (เปลี่ยน URL ให้เป็นของจริง):
   ```bash
   curl -X POST http://localhost:3000/api/notify-test
   ```
   ถ้าตั้งถูกต้อง จะเห็นข้อความ "✅ ทดสอบการเชื่อมต่อ Teams..." เด้งเข้าช่อง Teams ทันที

**หมายเหตุ:** ถ้ายังไม่ได้ตั้ง `teamsWebhookUrl` ระบบจะยังบันทึกข้อมูลได้ปกติ แค่ข้ามการแจ้งเตือนเฉยๆ (ไม่ error)

### ถ้าสร้าง Workflow ใน Teams ไม่ได้ (เจอ "No options available")

แปลว่าองค์กรปิดสิทธิ์ "Manage workflows" ไว้ระดับ Admin ลองทางเลือกนี้แทนได้ (คนละช่องทางจาก Workflows ในแอป Teams เลย อาจไม่โดนบล็อกเหมือนกัน):

1. เข้า **https://make.powerautomate.com** (Power Automate แบบเว็บเต็ม ไม่ใช่ในแอป Teams) ด้วยบัญชี Microsoft 365 เดียวกัน
2. สร้าง **Instant cloud flow** ใหม่ → เลือก trigger **"When an HTTP request is received"**
3. เพิ่ม action **"Post message in a chat or channel"** (connector: Microsoft Teams) → เลือกทีม/ช่องที่คุณเป็นสมาชิกอยู่ → ข้อความให้พิมพ์ `@{triggerBody()?['text']}`
4. Save flow → กลับไปที่ trigger "When an HTTP request is received" จะได้ **HTTP POST URL** มา
5. คัดลอก URL มาใส่ใน `config.json` ช่อง `teamsWebhookUrl` แล้ว restart server ตามปกติ

ทางนี้ใช้สิทธิ์ "สร้าง Flow ส่วนตัว" ซึ่งปกติเปิดกว้างกว่าสิทธิ์ "สร้าง Workflow ของทีม" — แต่ถ้าองค์กรบล็อก Power Automate/Teams connector ไว้ทั้งหมดก็จะติดปัญหาเดิมอยู่ดี ลองดูได้เลยเพราะไม่เสียอะไร ถ้าไม่ได้ผลใช้ระบบแจ้งเตือนในเว็บที่มีอยู่แล้วแทนได้เลยครับ (ไม่ต้องพึ่ง Teams เลย)

## วิธีใช้งาน

- **ดูข้อมูล**: ทุกคนเปิดเว็บดูได้เลยโดยไม่ต้อง Login ข้อมูลจะรีเฟรชอัตโนมัติทุก 15 วินาที
- **แก้ไขข้อมูล**: กด "Login" ใส่รหัสผ่าน Admin → แก้ไขค่าต่างๆ ในตารางได้ (ตัวเลข, Cover, Model, Hrs/Day) → ระบบจะไม่บันทึกทันที จนกว่าจะกดปุ่ม **"บันทึก"** สีม่วง (จะมีจุดสีส้มเตือนว่ามีการแก้ไขที่ยังไม่ได้บันทึก)
- เมื่อกด **บันทึก**: ข้อมูลทั้งหมดจะถูกเซฟลงเซิร์ฟเวอร์ + ส่งแจ้งเตือนเข้า Teams ทันที (ถ้าตั้งค่าไว้ ระบุชื่อผู้บันทึกจากช่อง "ชื่อผู้บันทึก" ที่กรอกไว้)
- ระหว่างที่มีการแก้ไขค้างอยู่ (ยังไม่กดบันทึก) ระบบจะไม่ดึงข้อมูลใหม่จาก server มาทับ เพื่อกันข้อมูลที่กำลังแก้หาย
- **กระดิ่งแจ้งเตือน** (มุมขวาบน): ทุกครั้งที่มีคนกดบันทึก ทุกคนที่เปิดหน้าเว็บค้างไว้จะเห็น toast + ได้ยินเสียงภายใน ~15 วินาที และเลขแดงที่กระดิ่งจะเพิ่มขึ้น คลิกกระดิ่งเพื่อดูประวัติว่า process ไหน model ไหนถูกอัปเดต โดยใคร เมื่อไหร่ (ล่าสุด 30 รายการ)
- ปุ่ม **1 Day / 1 Week / 1 Month**: สลับช่วงวันที่แสดงในตาราง โหมด 1 Month จะกว้างเกินจอ เลื่อนซ้าย-ขวาดูได้

## Auto Plan (คำนวณ LC / BW จากแผน CW)

กรอกจำนวนเครื่องแค่ที่ CW แล้วเปิดเมนู "⋮" → **Auto Plan** ระบบจะคำนวณเป็นทอดๆ ให้ว่า LC และ BW ต้องใช้กี่เครื่อง ในช่วงวันที่ที่กำลังดูอยู่ (1 Day / 1 Week / 1 Month)

1. Pcs ของ CW = เครื่อง × (Hrs/Day × 3600 ÷ MCT × OA%) ตามค่าของกลุ่มนั้น
2. Pcs ที่ LC ต้องผลิต = รวม Pcs ของ CW ทุกโมเดลที่ BOM ชี้มาที่ LC ตัวนั้น × อัตราส่วน
3. เครื่อง LC = Pcs ที่ต้องผลิต ÷ Pcs ต่อเครื่องต่อวันของกลุ่ม LC แล้วทำแบบเดียวกันต่อจาก LC ไป BW (BW ผลิตวันเดียวกับ LC)

**อายุงาน LC 14 วัน:** งาน LC ที่ CW ใช้วันที่ D ต้องผลิตในช่วง D-14 ถึง D (หมดอายุวันไหนต้องใช้ให้หมดภายในวันนั้น) ตั้ง "ผลิต LC ก่อน CW ใช้ … วัน" ได้ในหน้าต่าง Auto Plan (0 = วันเดียวกัน) ถ้าวันที่ต้องผลิต LC หยุด (Hrs/Day = 0) ระบบจะเลื่อนไปผลิตวันทำงานก่อนหน้าให้เอง แต่ไม่เกิน 14 วัน ถ้าหาวันไม่ได้หรือวันผลิตอยู่ก่อนช่วงที่แสดง จะขึ้นเตือน ในตารางผลลัพธ์ LC จะบอก "ใช้ก่อน" (วันหมดอายุ) ของงานที่ผลิตแต่ละวัน

ต้องตั้ง BOM (เมนู "จัดการแหล่งวัตถุดิบ") ให้ครบก่อน โมเดลที่ยังไม่ได้ตั้งจะขึ้นเตือนและไม่ถูกนำไปคำนวณ ผลจะเติมลงตาราง LC/BW เมื่อกด "นำไปใส่ในแผน" และยังไม่ถูกบันทึกจนกว่าจะกดปุ่ม **บันทึก**

## ข้อจำกัดที่ควรทราบ

- **ควรมี Admin แก้ไขทีละคนต่อครั้ง** ถ้ามีสอง Admin แก้พร้อมกันแล้วกดบันทึกไล่เลี่ยกัน คนที่กดทีหลังจะเขียนทับข้อมูลของคนที่กดก่อน (ระบบยังไม่มีการรวมข้อมูลแบบ real-time collaborative)
- รหัสผ่าน Admin เก็บแบบ plain text ใน `config.json` และถูกจำไว้ใน sessionStorage ของเบราว์เซอร์ระหว่าง session — เหมาะสำหรับเครื่องมือใช้ภายในทีมเท่านั้น ไม่ควรเปิดให้เข้าถึงจากอินเทอร์เน็ตภายนอก
- ข้อมูลทั้งหมดเก็บอยู่ในไฟล์ `data/store.json` — แนะนำสำรอง (copy) ไฟล์นี้เป็นระยะ
